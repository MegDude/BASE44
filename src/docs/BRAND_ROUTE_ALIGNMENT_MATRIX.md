# Downtown Perks Brand Route Alignment Matrix

## Purpose

This file turns the brand-route recommendation into a repo-native content spec. It is meant to guide rewrites of:

- `src/pages/downtown-perks/brands/Index.jsx`
- `src/pages/downtown-perks/brands/Yeti.jsx`
- `src/pages/downtown-perks/brands/HotelVanZandt.jsx`
- `src/pages/downtown-perks/brands/ThePaseo.jsx`
- `src/pages/downtown-perks/brands/Rivian.jsx`
- related partner brand surfaces

## Voice model

Every brand page uses two voices:

1. Brand truth
   - what the brand is actually about
   - what kind of public signal or positioning it carries
2. Downtown Perks intelligence layer
   - how Downtown Perks converts that brand energy into measurable local action

Do not write brand pages entirely in Downtown Perks strategy jargon.

## Page structure

1. Hero
2. Why this brand fits downtown
3. What the activation layer does
4. Best use cases
5. Bottom line
6. CTA

## Brand overview copy rules for `/partners/brands`

Keep:
- “Brand partners”
- context-based activation
- source-aware measurement
- district relevance

Avoid:
- generic campaign filler
- repeated “surface/layer/intelligence” copy in every module
- claiming live campaign behavior without proof

## Logo sourcing rules

1. Use only official brand-owned sources or supplied brand kits.
2. Do not redraw, respacing, or approximate logos.
3. Default to monochrome lockups in the Downtown Perks UI.
4. Apply equal visual treatment:
   - same max height
   - same padding
   - same clear space
5. Do not use third-party vector/logo sites as a source of record.

## Content caution

If current public evidence is directional rather than explicit:
- say “current brand signals suggest”
- say “the page should align to”
- do not overclaim active campaigns
