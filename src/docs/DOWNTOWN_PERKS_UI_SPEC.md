# Downtown Perks UI Spec

## Design Goal

The product should feel like a calm, premium, mobile-first city interface.

Every public and product surface should reinforce that the map is the main interaction layer, not a supporting widget.

## Visual Language

Use:

- softly lit off-white backgrounds
- deep navy for structure and primary actions
- gold only as a highlight or status accent
- thin dividers
- precise card hierarchy
- compact chips and controls
- drawer and bottom-sheet interactions
- subtle shadows and refined depth

Avoid:

- loud gradients
- coupon aesthetics
- tourism imagery as the main product signal
- enterprise dashboard chrome
- rainbow category systems
- heavy card stacking that feels like a wireframe

## Interaction Principles

Search starts the experience.

The map holds the system together.

Details should appear in context through drawers, panels, and sheets wherever possible.

Selected markers and selected cards must stay visually synchronized.

Radius, proximity, live status, save state, RSVP, and redemption states should be visible as product signals, not buried as secondary copy.

## Homepage Structure

1. Hero and map entry
2. Operating layer explanation
3. Resident decision loop
4. Four-system platform modules
5. Platform proof
6. Rollout and CTA

## Component Standard

Buttons should be navy-led, square-ish with slight radius, and use light text.

Gold should only appear in small accents, selected detail, or proof signals.

Map controls should be compact, quiet, and highly legible over the map surface.
