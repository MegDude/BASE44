- Brands
- Hotels

- District pages

- AI search intelligence
- SEO content

## North Star

Downtown Perks is a neighborhood discovery system.

Every entity exists to help someone understand:

- What is this?
- Where is it?
- Why should I care?
- What can I do next?

The image should answer most of those questions before the copy begins.

## Inventory Layers

Layer 1: Entity Registry

Every entity contains `id`, `slug`, `name`, `entityType`, `category`, `subcategory`, `district`, `address`, `lat`, `lng`, `status`, `source`, `updatedAt`, `description`, `primaryImage`, `galleryImages`, `thumbnail`, `actions`, `inheritance`, `seo`, and `searchText`.

Valid entity types:

- `building`
- `listing`
- `hotel`
- `restaurant`
- `bar`
- `coffee`
- `retail`
- `wellness`
- `brand`
- `event`
- `perk`
- `service`
- `civic`
- `district`

Layer 2: Visual Registry

Every production entity can resolve a hero image, thumbnail, gallery, fallback, and inheritance strategy from `heroImageRegistry.ts`.

## Image Inheritance

Unit listings inherit building imagery unless MLS photography exists.

Image priority:

1. Actual place photography
2. MLS photography
3. Building hero
4. District hero
5. Category fallback

Never invent MLS photography, architecture, interiors, prices, beds, baths, square footage, MLS numbers, status, or availability.

## Legends Real Estate

Legends is a residential discovery layer, not a standalone listing layer.

Source hierarchy:

1. MLS
2. Luxury Presence
3. Legends Feed
4. Building Registry
5. District Registry
6. Downtown Perks Inventory

MLS wins whenever MLS data exists.

Listing drawers must show property facts directly: price, bedrooms, bathrooms, square feet, MLS number, status, days on market, and available through Legends Real Estate.

## Drawer System

Resident drawer structure:

Hero image, metadata, headline, summary, property facts, building story, district story, nearby, actions.

Partner drawer structure:

Hero image, metadata, headline, opportunity narrative, resident narrative, building story, activity context, actions.

Remove permanently:

Tabs, cards inside cards, statistics grids, active perk badges, pill buttons, nested panels, dashboard layouts.

## Search Intelligence

Resident mode surfaces:

Coffee, Dinner, Events, Perks, Nearby, Tonight.

Partner mode surfaces:

Activity, Campaigns, Properties, Events, Perks, Trends.

AI responses should resolve against `production-map-inventory.json` before generating recommendations.

## Current Coverage

The current generated inventory is honest to the committed local source data. It includes a coverage block with requested production targets and available local counts. Missing production-feed records must be imported; they must not be fabricated.
