# Downtown Perks Page Consolidation + Content Reduction System

This specification applies to venue, hotel, property, brand, civic, campaign, partner, and showcase pages.

## Objective

Reduce repetition, increase clarity, improve reading rhythm, reduce scrolling, and remove component duplication.

Downtown Perks pages should feel like one editorial story, not a sequence of cards, rails, metrics, and repeated CTAs.

## Core Rules

1. Every major page uses one content rail: `--dp-content-rail`.
2. Horizontal rails are allowed only for true comparison or navigation.
3. Maximum rail count per page: one primary media rail and one optional directory rail.
4. Repeated concepts must be merged into one section.
5. Content belongs on the white canvas. Glass is reserved for navigation, search, controls, and drawers.
6. Each section must introduce new information.
7. If a card can be a sentence, do not create a card.
8. If users do not need to compare items, do not create a rail.
9. Each section gets one primary action and no more than two supporting actions.
10. Every section must answer: what new information is introduced here?

## Required Section Pattern

Use editorial lists instead of card grids:

```txt
CONTEXT
STORY
MEANING
```

Use directory rows only when navigation is the purpose:

```txt
CATEGORY
DESTINATION
PURPOSE
ACTION
```

## Reference Structure

The Stay Put page is the reference implementation:

```txt
Hero
How Stay Put Becomes A Habit
Where Stay Put Appears
Monday Meetups
QR Journey
What Stay Put Learns
What The Night Showed
Campaign Ideas
Why It Works
Contact
```

Remove duplicate metrics, duplicate benefits, duplicate CTAs, duplicate introductions, repeated horizontal rails, and repeated card systems.

## Final Standard

Less UI. More meaning.

The strongest Downtown Perks pages should feel like an editorial neighborhood guide, not a feature catalogue.
